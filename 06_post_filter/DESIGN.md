# 06_post_filter 설계

## 목표
05_black_litterman이 유니버스 전체(현재 99개)에 대해 낸 비중을 받아서, 실제로 들고 갈 수 있는 형태(종목 수 제한 + 집중도 캡)로 가공한다. BL 수식 자체는 05에서 끝났고, 여기는 순수하게 "그 결과를 어떻게 추려서 보여줄까"만 다룸.

## 05에서 분리한 이유
원래 05 안에서 상위 N개 추리기 + 발행사 비중 캡까지 같이 했는데, "삼성전자 보통주/우선주가 따로 캡 걸려서 사실상 같은 회사 비중이 과하게 잡힌다"는 문제를 고치다가 섹터 캡까지 필요해졌고, 섹터 분류 데이터 자체가 없어서(KRX 공식 API에 없음, LLM으로 분류해야 함) 범위가 "BL 계산"에서 "외부 데이터 분류 + 포트폴리오 가공"으로 커짐. **BL 수식과 사후 가공 규칙은 서로 다른 속도로 바뀌는 결정**이라(전자는 거의 고정, 후자는 N/캡 값을 자주 튜닝할 대상) 모듈을 분리.

## 핵심 설계 결정
- **입력**: `05_black_litterman.portfolio_weights`의 최신 (as_of_date, label) 스냅샷 — 유니버스 전체, 가공 전.
- **발행사(issuer) 그룹 캡**: KRX 보통주/우선주처럼 티커는 다르지만 같은 회사인 경우, `securities.name`에서 "보통주"/"N우선주" 접미사를 떼서 묶고 그룹 합계로 캡을 건다 (05에서 만들었던 `fetch_issuer_groups`/`_cap_and_renormalize`를 여기로 이동).
- **섹터 캡**: `securities.sector`가 KRX는 실제 업종이 아니라 "소속부"(시장 등급) 값이거나 NULL이라 지금 당장은 못 씀. 1차로는 **발행사 캡만** 적용하고, 섹터 캡은 사람 손으로(또는 LLM으로) 분류한 섹터 데이터가 들어온 뒤에 추가 (향후 과제 참고).
- **상위 N개 선별 + 재정규화**: 비중 내림차순으로 N개(기본 10, 파라미터로 노출) 추린 뒤, 캡을 다시 적용하며 재정규화. top-N을 자르는 시점에 캡이 깨질 수 있어서(잘려나간 티커의 비중이 남은 N개로 흡수되며 그룹 합계가 캡을 넘을 수 있음), 캡은 top-N 선별 **이후**에 최종적으로 한 번 더 강제.

## 처리 흐름 (`run_post_filter.py`)
1. 05의 `portfolio_weights`에서 최신 (as_of_date, label) 비중 조회
2. 상위 N개 선별 (0 비중 제외)
3. `fetch_issuer_groups`로 발행사 묶고, 비중을 1로 재정규화한 뒤 `_cap_and_renormalize`로 그룹 캡 강제
4. `final_portfolio`에 저장 (as_of_date=오늘 실행일, label)

## DB 스키마
- `final_portfolio(as_of_date, label, ticker, weight)` — PK (as_of_date, label, ticker). 05의 `portfolio_weights`와 스키마는 같지만 별도 테이블 — "가공 전/후"를 명확히 구분해서 보관.

## 라벨(label) 시스템
동일 패턴: `label='default'`는 나이트리 자동 실행.

## 향후 과제
- **섹터 캡 추가**: `securities.sector`를 실제 업종 분류로 채워야 함 (KRX 공식 API엔 해당 엔드포인트 없음 — 확인됨). LLM으로 유니버스 종목을 분류해서 DB에 캐싱하는 방식을 검토했었는데(유니버스가 주 1회 바뀌니까 새 종목만 매번 분류), 구현은 보류 상태. 데이터 준비되면 발행사 캡과 같은 패턴으로 섹터 캡 추가.
- 다음 단계(일일 보고서/LLM 정성 필터링)는 이 `final_portfolio`를 입력으로 받음.
