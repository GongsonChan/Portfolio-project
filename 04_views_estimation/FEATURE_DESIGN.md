# 04_views_estimation - 피처(팩터) 설계
 
## 타겟
각 종목의 **21거래일(월간) 앞 초과수익률(excess return)**을 예측 (BL의 Q). 라벨 = `(미래 21거래일 종목 누적수익률) - (같은 기간 매칭 시장지수 누적수익률)` — KOSPI/KOSDAQ는 ^KS11, US는 ^GSPC. 원래 수익률(raw return) 그대로 예측하게 하면 타겟 변동의 대부분이 "시장 전체가 오르내리는" 공통 성분이라 모델이 학습 가능한 종목별 상대 신호가 노이즈에 묻혀버림 — 그래서 시장 성분을 빼서 타겟을 종목 고유(idiosyncratic) 성분으로 좁힘 (시퀀스 모델 입력에 이미 적용했던 초과수익률 변환과 동일한 이유, `labels.py` 참고). 호라이즌/재학습 주기 등 배경은 `PROJECT.md`/`DAILY_UPDATE.md` 참고.

## 피처 목록
펀더멘털 데이터(PER, 부채비율 등)가 없어서 **가격/거래량 기반 팩터**로 한정.

### A. 모멘텀
- 1개월 / 3개월 / 6개월 누적수익률
- 12-1개월 모멘텀 (02_filter와 동일 로직 재사용)
- 최근 1주 수익률 (단기반전 신호)

### B. 변동성/리스크
- 실현변동성 (1개월/3개월/1년)
- GARCH 예측변동성 (`cond_vol`, 03_sigma_estimation 결과 재사용 — 재계산 안 함)
- 베타 (KOSPI 또는 S&P500 대비, 종목 시장에 맞는 지수로 롤링회귀)
- 이디오싱크라틱 변동성 (베타로 설명 안 되는 잔차변동성)
- MDD (최근 1년)
- 수익률 skewness, 최근 1개월 최고 일별수익률(MAX 효과)

### C. 유동성
- 거래대금 (최근 60일 평균, log)
- Amihud 비유동성 지표: `mean(|daily_return| / dollar_volume)`

### D. 기술적 지표
- RSI(14일)
- 이동평균 괴리율: `현재가/50일이평 - 1`, `현재가/200일이평 - 1`
- 볼린저밴드 %B (20일, 2표준편차)
- 거래량 서지: `최근5일평균거래량 / 최근60일평균거래량`

### E. 규모
- 시가총액 (log)
- 52주 고점 근접도 (`close_price` 기준 — 알려진 한계는 `03_sigma_estimation/DESIGN.md` 참고)

### F. 시장/매크로 (그날 전 종목 공통값)
- KOSPI 수익률 (1주/1개월/3개월)
- S&P500 수익률 (1주/1개월/3개월)
- KOSPI 실현변동성, S&P500 실현변동성

### (G. 횡단면 순위는 제외)
트리 기반 모델은 피처의 절대적 스케일에 크게 영향 안 받아서(분기 기준 학습) 순위 변환 없이도 패턴을 잘 잡음. 선형모델(Ridge 등) 쪽엔 도움될 수 있지만, 그 때문에 "유니버스 기준 매번 순위 재계산"하는 복잡도를 지금 추가하는 건 과함 — 선형모델 성능이 아쉬우면 나중에 추가 고려.

## 데이터 적재 전략 — "소급 계산 vs 매일 갱신"
가격(01)과 달리 팩터는 **이미 저장된 과거 가격으로 지금 바로 소급 계산 가능** (실시간으로 쌓일 때까지 기다릴 필요 없음). 그래서:

- **학습용 과거 패널**: 10년치 가격 데이터로 **한 번에 소급 계산** (주 단위 스냅샷, 약 520주) → `backfill_features.py`
- **매일**: 그날 스냅샷 계산/저장 (01의 daily_update_*.py와 같은 방식으로 "마지막 저장일 다음날 ~ 오늘" 갭 자동 보정) → `daily_update_features.py`
- 재학습 자체는 03_sigma_estimation과 같은 주기(주 1회)로 진행

**중요 — 테이블엔 매일 쌓이지만, 학습용 패널 조립 시엔 반드시 주 단위로 서브샘플링할 것.** 타겟이 21거래일(겹치는) 수익률이라, 인접한 날짜를 전부 학습행으로 쓰면 라벨이 대부분 겹쳐서 사실상 같은 정보를 중복 카운트하게 됨 (과거 대화에서 정리한 이유). `ml_features`를 매일 쌓아두는 건 (a) 그날그날 추론용 최신 피처 확보, (b) 나중에 다른 샘플링 간격으로 실험해볼 여지를 남겨두기 위함이지, 학습에 매일치를 다 쓰라는 뜻이 아님. 학습 데이터 조립 코드(아직 안 만듦)에서 `WHERE as_of_date IN (주 단위로 거른 날짜들)` 식으로 반드시 걸러서 써야 함.

## DB 테이블 (예정)
```sql
CREATE TABLE ml_features (
    as_of_date DATE NOT NULL,
    ticker VARCHAR(20) NOT NULL REFERENCES securities(ticker),
    -- A~G 각 피처 컬럼들...
    PRIMARY KEY (as_of_date, ticker)
);
```
